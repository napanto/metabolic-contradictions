## What changed from 5208dfa, as the oracle sees it

| Area | Change |
|---|---|
| Validator: codes, path, categories, factors | None. The selected site code is AST-identical, apart from the added `DISPLAY_ORDER`. |
| Q1 order | The order was result, groups, sample_size, comparison, analysis, significance, context. It is now result, comparison, significance, analysis, groups, sample_size, context. |
| Q1 texts | `q1_help`, `q1_absence` and `q1_frame` add the general rule and say how to treat empty and non-applicable fields. The help, how-to and examples of each check are rewritten. |
| New texts | `key_rules` (8 key-rule boxes), `q2_frame`, `missing_line`, `relevance_notice`. |
| Relevance | The title becomes «Does the extraction error change…» and the help is rewritten. `cannot_establish_comparison` is offered only after a Finding or Comparison problem (page rule). |
| Q2 | The help is rewritten. After «No» on «Measures and comparisons», the page offers only comparator, other and outcome_definition, instead of all 15 factors (page rule). |
| Q3–Q5 | The help is rewritten. The q4 «opposite» option becomes «Both find an effect or association, but in opposite directions». |
| Empty checks | When every value of a check is missing, the page offers only `missing_from_extraction` (page rule). |
| Presentation | The site's own renderer is used: the fixed «Study population» and «Comparison group» slots, the «None: …» texts and the role suffix. Labels include «Name used in the study» and «Direction of the estimate». The comparison tables are those of Q2–Q5. |
| Guidelines | The site's new English guidelines. Only the participant paragraph about AI tools is removed, as before. |

The three page rules are not enforced by the server validator, so a site export can contain them only from pages loaded before the change. For the oracle they are enforced in `page_offer_issues`. An answer outside them is invalid; it is never repaired.

## Prompt

Antonio approved three reductions, and the rules are not reworded:
- the whole-abstract `extraction` section is removed from the pair prompt;
- the JSON is compact;
- the field glossary keeps only the response fields of a pair (`instrument_version`, `pipeline_version`, `item_id`, `task`).

The preamble loses only its sentence about the extraction task.

Three path rules were added or rewritten:
- one rule for each of the page rules above;
- the null rule of the strict wire, which replaces «omit … rather than writing null».

The input glossary drops `extraction`, the old renderer's key, and describes the presentation fields.

**Sizes** (estimated at 4 characters per token):

| Part | Before | After |
|---|---|---|
| System prompt | 36,983 characters (~9.2k tokens) | 39,446 characters (~9.9k tokens) |
| User message, median of the 36 handoff pairs | 21.9k characters | 24.7k characters (max 31.2k) |
| Wire schema | 4.05k characters | 4.43k characters |

The reductions removed about 6.5k characters, but the site's own text grew by about 9k: the key rules, the longer help texts and the guidelines.

## Strict wire

`v2-pair-required-null-61c08a1` comes from `staging/v2_pair_wire_recovery`:
- every property is required, and an unvisited branch is `null`;
- a static strict-subset lint must pass;
- decoding removes only the structural nulls, then the site validator and the page rules run.

Category, factor and diagnostics are derived exactly as for a student answer.
